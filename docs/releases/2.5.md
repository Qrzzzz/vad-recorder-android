# 2.5：异常片段恢复与真实输入状态

范围：#23、#24；接续 2.4.1 的会话控制、2.4.2 的来源与完整性、2.4.3 的 I/O 改进。

- 新片段开始写音频前，同步保存实际客户端采样率、声道、16 位 PCM 位深、来源文件名和创建时间。参数与片段位于同一可信录音目录。
- 可控销毁从“无条件删除片段”改为“尽量收尾保存”。存储失败也先尝试收尾；收尾失败保留待恢复片段。原有正常停止的短噪声过滤不变。
- 打开录音列表、刷新或开始监听时恢复当前可访问录音目录中的片段。只保留完整采样帧，按原文件名提交，成功后显示“异常中断”。恢复不知道人声时长，不伪造该值。
- 参数不足的旧残留不猜成 16 kHz；空片段、冲突和暂时无法恢复的片段单独保留，显示说明，支持刷新重试和确认清理。残留不会进入正常录音列表。
- 恢复跳过正在写入的文件；重复执行不生成副本、不覆盖同名正式录音。删除先移除恢复源，失败则保留正式音频，避免之后恢复出用户已删除的录音。
- API 29 起注册录音配置回调，并读取活动采集配置，分别显示系统静音与正常监听；解除后继续原会话。API 26–28 不调用新接口。全零音频本身不构成故障证据。

这是数据保留策略增强，不是将原来的销毁删除策略重新解释为随机 Bug。`onDestroy` 不保证在系统终止时执行；断电、存储损坏、强杀时尚未持久化的数据不能保证零损失。保留参数也不意味着所有历史残留都能恢复。

平台依据：[Android Sharing audio input](https://developer.android.com/media/platform/sharing-audio-input)。验证证据与边界见 [2.5 验证记录](../internal/v2.5-validation.md)。
