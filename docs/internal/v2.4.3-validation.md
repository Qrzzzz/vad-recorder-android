## 最低验收

- PCM：16 kHz、44.1 kHz；零、正负值、Short 极值、非满帧、超长 length、空数组和空写入。对照旧逐字节算法，PCM 数据逐字节相同；缓冲扩容后短帧不写入残留尾部。头部、写入失败、同步提交、防覆盖及重复关闭回归通过。
- 写入粒度：20 ms 帧连续保存一秒，两种采样率均为 50 次批量 PCM 写调用；旧实现由源码计算分别为 32,000 / 88,200 次单字节调用。这不是物理磁盘刷新次数，也不是耗电测量。
- 后台 I/O：注入独立线程 dispatcher，在录音根解析与删除入口断言线程不是调用线程；扫描、播放前校验、删除均通过 main-safe 仓库接口。无法枚举已有目录会报告失败，空目录正常返回空列表。
- 请求顺序：可控延迟与不响应取消的扫描覆盖连续刷新、删除期间刷新、删除完成后旧扫描返回、ViewModel 清理后的晚到结果；旧结果不能覆盖新结果。加载失败保留已有列表，后续可重试；音频删除失败及 JSON 部分清理失败保持现有契约。
- 懒加载：日期摘要是独立 item，每段录音使用带类型前缀的来源路径 key 和 recording contentType。测试验证同一晚 500 段不整组组合；插入后打开的菜单仍删除原目标，播放进度属于原片段；删除其他行不会转移播放器，删除当前行移除播放器。

## Android UI 验收

代表环境：本机 `lcg_113_api30_probe`，Android 11 / API 30、x86_64 模拟器，隔离包 `com.qrz.voicetriggerrecorder.acceptance`。不操作正式包数据。

- `HistoryAcceptanceTest`：2/2 通过。500 个一秒静音 WAV 放在同一晚，中间位置观察到 5 个已组合录音条目；插入后扫描 501 个文件的一次观察值为 232 ms（包含测试等待开销，不作为门槛或基准比较）。末尾定位、菜单、播放、连续刷新和删除均通过。另覆盖 20 晚共 40 段及 Activity 重建。
- `PlaybackAcceptanceTest`：2/2 通过。中英、深浅色、暂停续播、触摸与无障碍 seek、重播、后台、切换、删除和重建。
- `TransferAcceptanceTest`：3/3 通过。真实 DocumentsUI 导出后比对 SHA-256，真实分享面板跨 UID 接收、只读授权、取消和界面重建。更新旧夹具以显式创建 JSON，不再依赖浏览时写入；等待异步历史列表；兼容 Android 11 用测试应用包名显示分享目标的行为。
- `DeviceAcceptanceTest`：权限普通拒绝后重试、真实文件描述符写入/提交失败提示 2 项通过。声学录音测试 1 项未通过：模拟器没有检测到通过扬声器播放的人声，等待 RECORDING 超时。本轮未连接物理设备，不能据此声称完成真机声学或整夜验收。
- 已检查英语浅色菜单截图：日期摘要、独立录音卡、播放与更多菜单布局正常。测试截图写入隔离应用内部目录，便于在 Android 11 存储限制下提取。

不设置未经测量的耗电比例、跨设备统一响应时间或帧率门槛；未引入生产者—消费者队列、Room/Paging，也未迁移历史录音。

## 发布核验

按 PR → CI → 合并 → 附注标签 → Release 工作流发布。工作流核验版本、正式包名、非 debuggable 及既有签名证书，再上传 APK 和 `SHA256SUMS.txt`。发布后核对 GitHub API 的标签提交、工作流结论、附件数量/名称/大小及 digest；按用户要求不重新下载附件。
