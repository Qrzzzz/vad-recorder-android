# 2.5 验证记录

日期：2026-09-17。范围：#23、#24。版本 `2.5` / versionCode `14`。

## 文件契约

| 状态 | 识别与行为 |
| --- | --- |
| 完整正式文件 | 通过既有完整 WAV 校验；正常列表、回听、导出契约不变 |
| 参数已知的待恢复片段 | `.wav.part` 与版本为 1 的 `.wav.recovery` 参数记录；参数在写音频前同步。只按完整声道采样帧恢复，不改变原文件名 |
| 参数不足的未知残留 | 参数记录缺失、损坏、不受支持或来源不匹配；保留并提示，不猜采样率、不自动删除 |

恢复结果区分 RECOVERED、PENDING、UNKNOWN、EMPTY、CONFLICT。重试保持同一来源身份；元数据提交失败保留恢复标记，下一次扫描补交，不复制音频。成功恢复的人声时长为空。

所有扫描限定 `RecordingStorage` 的当前可信根，跳过越界链接和活跃 writer。写入登记、恢复与删除互斥。删除先移除 partial，再移除参数记录，再删除正式 WAV/JSON；中途失败不先删除正式录音。残留清理不会删除正式 WAV。

原 `destroyRemovesActivePartialFile` 改为检验低于正常停止阈值的有效片段也能以 Destroy 原因保存；原按年龄删除测试改为检验新旧未知片段均保留；原写入失败和提交冲突测试改为检验待恢复结果及正式文件不变。并非删除原测试绕过契约变化。

## 本地与 Android 验证

Windows / Android Studio JBR，在英文源码副本 `D:\codex-builds\recorder-v25` 执行：

```powershell
.\gradlew.bat testDebugUnitTest lintDebug assembleDebug assembleRelease --console=plain
.\gradlew.bat -PdeviceAcceptance assembleDebug assembleDebugAndroidTest --console=plain
```

- 111 项单元测试：110 通过、0 失败、1 跳过。跳过的是已有 Windows FileProvider 路径语义测试；Linux CI 应执行该项。本轮新增测试包括 API 26、28 降级和 API 28、30 输入状态注入。
- Lint：0 errors、34 warnings；保留已有 API 常量提示、依赖升级提示、资源与样式建议，不将这些提示写成零警告。
- 正式 Debug、未签名 Release、隔离验收 APK 与 AndroidTest APK 构建通过。正式 Release 的 applicationId、`2.5` 与 versionCode `14` 已核对。
- 83 个源码、资源、测试和构建配置文件与工作目录逐文件 SHA-256 相同。中文路径的宿主构建问题沿用既有英文副本规避方式。
- 新增恢复测试覆盖：44.1 kHz PCM 逐字节恢复、立体声截断采样边界、空片段、未知参数、活跃 writer、同名冲突、重复扫描、删除与清理失败、元数据提交中断后重试。
- 故障写入补验：第一批 PCM 已有完整样本落盘、但成功写入计数尚未更新时，writer 和状态机仍尝试按磁盘长度收尾，不因计数为零而丢弃有效音频。
- 输入测试覆盖：普通全零正长度帧不报受限，受限状态不会被普通 read 清空，解除回到正常监听，停止后的旧回调无效，API 26/28 不进入新接口分支。

代表设备：`lcg_113_api30_probe`，Android 11 / API 30、x86_64 模拟器。隔离验收共 6 项通过：两阶段恢复 2 项、输入竞争 1 项、恢复提示与确认清理 UI 1 项、已有 500 段同晚录音和多晚列表回归 2 项。

Android 中断测试使用隔离包 `.acceptance`，分别以 `-e recoveryStage seed` 执行 `RecoveryAcceptanceTest#seedInterruptedFragment`、`am force-stop com.qrz.voicetriggerrecorder.acceptance` 结束该进程、再以 `-e recoveryStage recover` 执行 `#recoverAfterProcessRestart`。第一阶段故意不关闭 writer；第二阶段检查 44.1 kHz 参数、PCM 长度、恢复原因、重复扫描、未知旧片段和删除后不再出现。常规整套 instrumentation 未指定阶段时，这两个跨进程专项明确跳过，避免在同一进程伪造重启。

输入竞争测试使用另一个应用 ID `.inputprobe` 的隔离同源包，获取不同 UID。目标录音服务启动后，切换到 probe 开始监听，使平台按前台优先策略静音目标输入；检查目标服务仍在运行且通知显示受限，再停止 probe 验证目标解除。未安装 probe 时该专项测试明确跳过。

本轮输入竞争实际触发并通过，未使用 `inputSilenced` 注入代替平台事件。probe 由独立临时源码副本把 `deviceAcceptance` 的 `applicationIdSuffix` 改为 `.inputprobe` 后构建，正式源码没有添加 probe 产品变体。

复验曾被模拟器的 `Gboard keeps stopping` 系统弹窗遮挡，测试在 probe 界面就绪前失败，未到输入竞争断言。关闭该宿主弹窗后，输入竞争专项重新执行并通过（1/1）；测试同时增加了 probe 可滚动界面就绪检查。未修改正式应用来绕过宿主故障。

界面检查覆盖 320 × 640 小屏幕：未知残留状态、异常中断标签、确认后只清理残留、正式录音保留。截图发现悬浮提示遮挡录音行后，已改为列表内可滚动提示，并加强为实际可见断言；未将仅存在于语义树的条目算作可见验收。

本机日志与已检查截图曾保留在 `D:\codex-builds\recorder-v25-evidence`，包括成功的 `v25-input-final.log`、两阶段恢复日志及布局复验日志。发布准备时再次核对源码哈希与测试汇总后，按仓库发布流程将 3 个临时构建/证据目录和 23 个临时文件移入回收站。隔离 probe 测试应用已卸载，不操作正式包录音数据。
